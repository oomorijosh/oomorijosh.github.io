## How Does One Estimate Effort?
Estimating effort is not rocket science. It involves tracking an estimated time (based on your best guess) and comparing it to the actual time taken. That is all. When I needed to track my time, I made a small change to the related GitHub issue before starting work. Since GitHub records commit times, I could subtract the start time from the time I stopped working.

For example, if I began working on a task at 10:00 pm and finished at 11:30 pm, I would simply record 1.5 hours of effort. If I had already logged 2 hours on that task previously, I would add the new time (1.5 + 2) for a total of 3.5 hours. This method is a simple and consistent way to track effort without disrupting workflow.

## Why Should You Estimate Effort?
Effort estimation may initially seem unnecessary, but it becomes extremely valuable when planning larger projects. Estimating effort helps break down and delegate tasks more effectively. When looking at tasks such as “create page xx” or “implement pagination,” it is often difficult to intuitively understand how much time should be set aside. Even if the actual effort differs from the estimate, the process gives a reasonable expectation of the time commitment required.

A concrete example of this occurred during my final project for software engineering. One task was to create an admin panel. Without estimating effort, this task appeared small. However, once I considered the estimated time required, I realized it would likely take longer than expected due to things I haven't considered. As a result, I allocated more time to the task, which ultimately proved necessary. Over time, as I continued estimating effort, I noticed that my estimates became increasingly accurate.

## What would I change for Effort Estimation
At the beginning of the final project, we did not track effort estimation because we lacked experience with GitHub and task management. If I could change our approach, I would begin effort estimation from the very start. Tasks were harder to manage because the required effort was not recorded.

Additionally, non-coding tasks such as page mock-ups, GitHub Pages maintenance, and design planning were not tracked. Including these tasks as GitHub issues would have provided a more complete picture of the total effort required for the project. Recording all forms of work would greatly improve project planning and evaluation.
